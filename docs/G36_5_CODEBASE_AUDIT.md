[Worker imports](../backend/zeek_stream.py#L22-L27) · [Capture reader and cohort module](../ml/lab_capture.py#L13-L29)

## Proposed implementation specification

**Problem.** Current safeguards cover normal regressions and recorded replay, but several boundaries can accept inputs, identities, or evidence that differ from their documented contract. Analyst error handling and current project navigation also need targeted cleanup.

**Solution.** Fix eligibility at the point of use. Require immutable official evaluation and deployment identities, verify the effective local database destination, consume verified evidence exactly once per load, and keep valid analyst work usable when a dependent request fails. Prefer focused vertical changes and existing interfaces.

**Acceptance and test seams.** Preserve route URLs, response schemas, existing identifiers, promotion gates, and implemented offset/cursor contracts. Keep model bytes, feature order, operating point, sealed datasets, research inputs, and lab isolation intact. Test at the evaluator CLI, default ASGI startup, API and disposable PostgreSQL, file-backed import and replay, and rendered dashboard. Add the regression described in each proposed ticket. Also add a migration case that seeds both offline and continuous rows and proves downgrade to `0002` preserves only offline data, and pin a supported way to verify the frozen artifact without running the held-out evaluation. Keep application and documentation checks green for every accepted slice.

**Risk controls.** Stop before scoring on an unexpected official test digest. Keep explicit synthetic model injection for tests. Ensure an upload already within both caps keeps its former batch boundaries and retry keys. Where successful historical saves are possible, design resumable identities before changing boundaries. For evidence handling, keep existing registry files and digests readable. Flag any proposed compatibility break or new migration for approval before implementation.

**Out of scope.** G37 or lab execution, a full rewrite, a remote deployment or authentication redesign, fitting or retuning models, opening sealed data, changing historic evidence, mass wire or schema renames, and adopting a new job or event platform.
