# Herdr orchestration

Run `python -B tools/herdr/orchestrate.py --help` with Python 3.12 and native Herdr on Windows. The controller uses the local Herdr server and a SQLite ledger under LocalAppData. Supervisors coordinating these panes use the same ledger, trusted Git configuration, and a trusted PATH. The agent runtime owns sandboxing and tool permissions. The controller never answers approval prompts or runs Git publication commands.

1. Create a task with `create TASK OWNER REVIEWER --mode workspace`. Use `--mode tool-free` when the task requests a reply with no tool use. Verify the model and effective runtime policy for either mode before dispatch.
2. Put the objective, allowed paths, checks, and acceptance criteria in a brief. Use `send TASK BRIEF --verified-policy --worktree ABSOLUTE_PATH --baseline FULL_SHA` for workspace work. The controller checks the exact worktree and HEAD and requires a clean checkout by default. If the task depends on unpublished files, inspect their scope and exact contents before adding `--inputs-verified`.
3. Inspect the actual diff and test results. Record them in an evidence file with candidate file digests. Apply the human-first gate and release review with `review TASK EVIDENCE`. Send the independent reviewer a brief containing the approved evidence or its location and pass `--evidence EVIDENCE` to bind the dispatch to the release digest.
4. Verify the reviewer's claims, request a bounded revision with `revise TASK`, or record engineering acceptance with `accept TASK EVIDENCE`. Git publication and merge require separate human authorization.

Use `status --task TASK` for a single record, `status` for the full queue, and `audit` for transitions. The shared ledger permits three concurrent reservations and one NVIDIA-backed task across the configured MiniMax and Nemotron aliases. Keep the alias-to-provider mapping current. Transient reads can retry twice. Revision cycles are capped at two. The limits cover controller dispatches through that ledger.

After an uncertain send, inspect the same session and use `collect TASK` when its receipt arrives. For a verified response with a noncanonical receipt, pass the exact line to `collect TASK --observed-line LINE`. Use `abandon TASK --reconciled` only after confirming the original terminal is settled and checking for side effects. A live sender holds a per-agent lock and prevents abandonment. If the original session ended or was replaced, verify the prior session and any effects, then use the explicit `--session-ended` reconciliation option. The controller refuses that option while the original identity is still present or a replacement turn is active. Avoid replaying an uncertain prompt. Receipt and audit records track orchestration state. Verify actual changes and tests before acceptance.
